# VL53L1X 五路测距与 ROS 横移联动

当前固件使用五个 VL53L1X。前方已恢复为 VL53L1X；原左右两路保留；新增两路分别标注为“机械臂上方左”和“机械臂上方右”。所有模块持续采样、上报。任务阶段、左右比较和整车横移由 ROS 控制。

## 接线与编号

五个模块共用 I2C1：SCL 接 **PB8**，SDA 接 **PB9**，GND 与 STM32 共地。使用支持 3.3 V 供电和 I/O 的模块，VCC 接 3.3 V；I2C 上拉也接 3.3 V。XSHUT 各自单独连接，不能全部固定拉高，否则默认地址 0x29 会冲突。

| sensor_id | 标注 / 安装位置 | XSHUT 引脚 | 初始化后的 7 位 I2C 地址 |
|---:|---|---|---|
| 0 | 前方 | PE0 | 0x30 |
| 1 | 原左侧 | PE1 | 0x31 |
| 2 | 原右侧 | PE2 | 0x32 |
| 3 | 机械臂上方左 | PE5 | 0x33 |
| 4 | 机械臂上方右 | PE6 | 0x34 |

前方原 HC-SR04 的 TRIG/ECHO 接线移除，PA1 不再作为回波输入；PE0 改接前方 VL53L1X 的 XSHUT。PE3/PE4 为机械臂按键，PE5/PE6 专用于新增两路测距的 XSHUT。

上电时先拉低全部 XSHUT，再逐个启动、识别 VL53L1X 型号、分配地址并启动连续测量。单模块初始化失败时保持该模块 XSHUT 低，其余模块继续初始化。地址在重新上电后重新分配。

## STM32 上报接口

CAN1 为 500 kbit/s，标准数据帧 **0x110**，DLC=8。现有 ID 0/1/2 和报文布局保持不变，ROS 增加 ID 3/4 的解析。

| 字节 | 内容 |
|---:|---|
| 0 | 固定 0x01 |
| 1 | sensor_id，见上表 |
| 2..3 | distance_mm，uint16 小端，毫米 |
| 4..5 | sigma_mm，uint16 小端；当前不支持，固定 0xFFFF |
| 6 | status 状态位 |
| 7 | 每路独立递增的 sequence，255 后回到 0 |

status：bit0=有效，bit1=超量程，bit2=超时，bit3=I2C 错误，bit4=低质量，bit5=本地障碍停车。无效距离填 0xFFFF，有效位清零，不能将 65535 当成真实距离。

有效量程为 50–3000 mm；有效距离使用最近三个有效样本的中值。无效原始距离不进入滤波，避免历史有效值掩盖当前无效测量。轮询每 10 ms 检查一路，五路正常工作时各约 20 Hz。缺少新结果超过 200 ms 时上报超时。

诊断帧仍为标准 **0x111**，DLC=8：`01, sensor_id, error_code, consecutive_errors, distance_mm LE16, status, sequence`。错误码 1=I2C/初始化失败，2=超量程，3=采样超时；低质量时携带传感器原始测量状态码。初始化失败可能只上报一次，ROS 必须继续检查数据是否超时。

CAN 发送队列暂满时，传感器任务为每路保留待发送的距离和诊断，在后续 10 ms 周期重试，成功入队后清除待发送标志。诊断优先于距离入队；新距离替换同一路尚未入队的旧距离，新诊断替换同一路尚未入队的旧诊断。重试不等待硬件邮箱，不影响采样和本地障碍停车。成功入队只表示软件队列接受，实机收包仍需在上位机确认。

示例：上方左 500 mm、上方右 1000 mm，各自第 1 个有效样本：

```text
CAN 0x110: 01 03 F4 01 FF FF 01 01
CAN 0x110: 01 04 E8 03 FF FF 01 01
```

原前/左/右（ID 0/1/2）有效距离不大于 300 mm 时继续触发底盘本地停车。新增上方传感器（ID 3/4）用于任务目标比较，不参与该 300 mm 障碍停车判断，避免靠近任务目标时与 ROS 横移控制冲突。急停和 500 ms 上位机通信超时停车继续有效。

## ROS 阶段与横移逻辑

ROS 任务状态机进入指定阶段后启用上方测距横移，退出阶段、取消任务或急停时停止横移。STM32 无需额外的“启用横移”命令；它持续上报，ROS 在该阶段发送现有底盘控制报文。

按用户指定规则执行：

| 上方左测距 | 上方右测距 | ROS 底盘目标 |
|---|---|---|
| 500 mm | 1000 mm | 整车向左平移 |
| 1000 mm | 500 mm | 整车向右平移 |
| 两侧接近相等 | 两侧接近相等 | 停止横移 |
| 任一侧无效或超时 | — | 停止横移，等待新有效测距或任务状态机处理 |

提供可直接导入 ROS 控制节点的纯 Python 比较器：[tools/arm_upper_alignment.py](../tools/arm_upper_alignment.py)。它只返回 `+1=左、-1=右、0=停止`；ROS 底盘控制器负责速度限幅、车轮映射和电机方向。

默认距离差达到 50 mm 才开始横移，回到 20 mm 以内停止；中间区间保持已经确定的同向运动，反向的小幅噪声先停止。两路必须都有有效数据，且接收时间距当前不超过 200 ms、两路接收时间差不超过 100 ms。重复 sequence 不刷新有效期。进入阶段时清除旧测距，等待阶段内的新样本。这些默认值应结合实际安装和运动速度调整。

接入示例（运行于 ROS 节点，不在 STM32 内执行）：

```python
import time
from arm_upper_alignment import ArmUpperAlignment

alignment = ArmUpperAlignment()

# 进入/退出对应任务阶段时调用；实际阶段由现有 ROS 状态机决定。
alignment.set_enabled(True)  # 退出时改为 False，并发送停车

# 接收到 CAN 数据帧时调用，使用 monotonic 时间，避免系统时钟跳变。
alignment.update_can_frame(
    msg.arbitration_id, msg.data, time.monotonic(),
    is_extended_id=msg.is_extended_id,
    is_remote_frame=msg.is_remote_frame,
)

# 固定周期控制（例如 20 Hz）：
direction = alignment.lateral_direction(time.monotonic())
# ROS REP-103：+Y 向左；目标 vx=0，vy=direction*该阶段的低速横移速度，wz=0。
# ROS 节点将该目标交给现有底盘控制器，转换为四个电机的速度报文。
# direction=0 时应真正发送停止指令，不能仅停止发布而保留上一条速度。
```

使用现有 CAN1 标准 **0x100** 的 `0x01` 单电机速度命令或兼容 **0x201** 底盘命令发送车轮速度；需要停车可发送 `0x100: 03 FF 00 00 00 00 00 00`。ROS 控制节点仍须保持心跳，例如每 100 ms 发送 `0x100: 09 FF 00 00 00 00 00 00`。本仓库不包含 ROS 节点工程，此处提供比较器和接入接口，ROS 状态机和发布链路需要接到其对应工程。

“朝较短一侧移动”是否最终使两侧距离相等，取决于两个模块朝向及目标形状。联调时先确认横移对两侧距离差的影响，再确定该阶段结束条件和允许的移动范围。

## 验证

```powershell
python tools/run_host_tests.py
cmake --build build/verify-arm2
```

主机测试验证五路地址分配、失败模块隔离、五路轮询和 CAN 编号、上下两组停车作用域、无效原始测距，以及 ROS 比较器的阶段门控、左右方向、容差、超时和重复帧处理。模拟 I2C 不替代实机测试。接线和烧录完成后，还需检查五路实测数据，并在 ROS 对应阶段测试横移方向。
