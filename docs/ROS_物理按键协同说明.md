# ROS 与物理按键协同

物理启动键不负责生成速度或位置命令。ROS 先通过 CAN1 `0x100` 下发带同步标志的运动命令，固件接收并缓存后，操作员按下启动键，固件再按队列顺序发送同步触发。

ROS 应持续发送心跳命令 `09 FF 00 00 00 00 00 00`，建议周期为 100 ms。物理启动键不会刷新 ROS 心跳；没有近期有效 ROS 通信时，启动请求会被拒绝。心跳超时仍会执行本地急停。

物理按键事件使用标准帧 `0x112`、DLC=8：

| 字节 | 含义 |
|---:|---|
| 0 | 事件：`0x01` 启动 |
| 1 | 状态：`0x01` 按下 |
| 2 | 来源：`0x01` 物理按键 |
| 3 | 结果：`0x00` 已接受，`0x01` 已拒绝，`0x02` 执行失败 |
| 4..5 | 本地启动命令序号，大端；拒绝时为 `0` |
| 6..7 | 保留，填 `0` |

启动事件的 `0x00` 只表示请求已被固件接受。ROS 应保存字节 4..5 的序号，并等待普通 ACK 帧 `0x102`：`seq_hi, seq_lo, 0x05, result, 0, 0, 0, 0`。若事件结果为 `0x01`，ROS 不应认为运动已经启动；若收到 `0x02`，应记录同步触发执行失败。

收到启动事件后，ROS 应暂停继续追加新的同步运动命令，直到收到该序号的 ACK；这样一次按键对应的缓存命令集合是确定的。

由于 ACK 的 CAN ID `0x102` 高于事件帧 `0x112` 的仲裁优先级，实际总线顺序可能是 ACK 先于按键事件。ROS 应按序号关联两类帧，不要依赖它们的接收顺序。

收到电机故障或心跳超时事件后，ROS 应停止继续下发运动命令，待故障排除或通信恢复并完成安全复位后，再重新配置并缓存运动命令。
