# 给 ROS 工程的对齐提示词

复制下面整段交给处理ROS工程的代码助手：

```text
请只检查和修改当前ROS工程，使其与已精简停车职责的STM32对齐。先读实际源码说明停车决策链，再作最小必要修改；不要修改STM32，不要吞负ACK、关闭故障保护或切换无应答模式掩盖问题，只做必要的少量回归。

固件当前约定：
1. ROS→CANable→STM32 CAN1→CAN2→四个驱动器，500 kbit/s。STM32 motor_idx=0..3默认映射物理地址1..4，FF表示全部。保留ROS现有逻辑轮序/方向映射，核对源码，避免重复重排。
2. STM32只保留显式急停、有效ROS通信中断超过500 ms、真实严重电机故障、运动实际提交/发送失败/原生负应答/确认超时的停车。停车取消待执行运动和同步缓存，恢复后不重放失败/取消运动。
3. STM32已删除距离避障/制动阈值/滞回/车体几何推算、运行中逐轮命令更新租期、反馈新鲜度和位置参考准入、sync=0四轮收集。参数错误、缓存不完整、队列陈旧只拒绝，不因此额外全车停车。不要依赖STM32处理导航停车。
4. ROS统一决定距离制动、侧移绕行、任务结束停车、cmd_vel/规划器/遥控输入超时、反馈新鲜度异常的处理。尤其：CAN桥心跳继续而运动指令源停止更新时，STM32不会在500 ms后停车，ROS必须独立监测上游命令源时间戳，使用合理可配置超时主动发四轮零速或急停；不能持续转发陈旧非零速度。停车覆盖所有运动出口，防止旧非零命令被队列/定时器重新发出。正常制动可四轮零速，故障/需取消缓存时显式急停。
5. 0x100标准帧DLC8：[cmd,motor_idx,value int32 LE四字节,param0,param1]。速度cmd=01，整数RPM，param0加速度，param1=0即时/1缓存。普通运行逐轮sync=0，不发送05、不合成实体按钮事件。全车急停：03 FF 00 00 00 00 00 00。心跳：09 FF 00 00 00 00 00 00，建议100 ms一次；其他有效控制通信也刷新STM32存活时间。
6. 保持默认WAIT_ACK。0x102：[seq_hi,seq_lo,cmd,result,0,0,0,0]，seq由STM32分配，0x100无主机序号字段。result=0表示终态成功：默认运动收到匹配原生02，不是已到位；result=1仍是真实拒绝/失败。等待本身不发负ACK。不能用“最近一帧速度”武断关联失败电机，也不要按CAN1所有帧盲增本地序号。0x103字段不变，保留execution_failure保护和诊断日志。
7. 保留真实实体按钮启动：四轮sync=1缓存并等待各轮确认，再等待0x112实体事件。事件[01,01,01,result,seq_hi,seq_lo,0,0]：result=0只是请求接受，1拒绝，2后续执行失败。启动ACK的cmd=05，默认匹配广播FF 66 6B后的FF 02 6B（地址映射第一项，默认1）才成功。按同序号关联，初始事件0不代表驱动已启动。心跳正常时缓存可等待按钮数秒。
8. 0x110：[01,sensor_id,distance_mm LE16,sigma_mm LE16,status,sequence]，原始距离不扣安装内缩，sigma不支持为FFFF。sensor_id=0前/1左/2右/3和4机械臂两侧/5后；0x111诊断定义不变。无效距离FFFF且VALID(bit0)清零。多数时间无回波正常，不能视为零距离/近障碍或直接禁止普通导航；仍监测真实采集/通信异常。有效新距离必须参与制动和绕行，安装补偿、车体几何、阈值/滞回由ROS统一管理，3/4按任务阶段用于机械臂对齐。不能拿旧有效距离当新采样无限续期。
9. 0x101状态/故障事件、0x103统计、原生扩展应答转发不变。正常83不是故障，bit7是掉电记录；真实严重故障/失联仍须保护。健康空闲轮询每轮速度约160 ms、位置约320 ms，运动占用时更慢；核对反馈时间戳/超时策略，避免正常轮询误判、旧反馈反复上报被当成新实测。不要修改CAN字节格式或关闭原生确认。

请给出实际修改文件、统一停车决策路径、上游输入超时但心跳继续时的处理、少量必要回归结果和架空实测步骤。至少覆盖：有效距离制动/绕行、正常无回波可导航、速度源断流主动停车、实体按钮启动/失败关联、负ACK/驱动故障/失联仍保护。
```
