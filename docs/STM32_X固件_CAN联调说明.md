# STM32 / Y42 X 固件 CAN 联调说明

当前实现为五电机、Y42 **X 固件**、固定校验字节 `6B`。旧的《STM32 四轴协议转换与控制使用说明》中的 Emm 报文和四轴限制不适用于当前实现。

## 接口与启动

- CAN1 接上位机，CAN2 接电机；外部晶振为 8 MHz 时，两路 CAN 均为 500 kbit/s。
- 启动完成后，按默认地址 1、2、3、4、5 发送五条 `F3 AB 01 00 6B` 使能命令（DLC=5），使电机锁轴。
- CAN 中断在消息队列和驱动初始化完成之后启用。
- 所有控制、状态、心跳和测距任务成功创建后才启用 CAN 并使能电机；任务创建失败会进入错误处理。
- 两路 CAN 发送都经过各 64 帧的软件队列。邮箱满时保留数据，控制任务每 1 ms 尝试发送；硬件开启发送 FIFO 优先，保持分包顺序。
- 一条本地生成的多包命令整体入队；容量不足时整条拒绝，避免只发送第一包。
- 队列容量有限。溢出或 HAL 发送失败计入通信统计；总线持续无 ACK 时仍需检查总线连接和 CAN 错误寄存器。
- 指令处理每 10 ms 最多取出 16 条，每条之间恢复中断并服务 CAN。避免旧的每轮一条、最多 100 条/秒限制导致五电机连续控制积压。

## 上位机命令

### 标准帧 0x100

固定 8 字节：`cmd, motor_idx, value(int32 LE 四字节), param0, param1`。

- `motor_idx=0..4` 对应五个电机，`FF` 表示全部电机。
- `01`：速度，value 单位 RPM；param0 为 X 固件加速度 RPM/s（本接口范围 0..255），param1 为同步标志。
- `02`：位置，value 保留旧接口的脉冲单位，以 3200 脉冲/圈换算为 X 固件的 0.1°；param1 的 bit0..1 为模式 0/1/2，bit2 为同步标志。当前使用 FB 直通限速位置模式，不使用加速度字段。
- `03`：全部急停。使用独立的优先槽，普通命令队列满时仍可接收；已有急停待处理时，重复请求返回否定 ACK。执行时清除待执行上位机命令、驱动等待队列和 CAN2 待发送报文，取消硬件邮箱，然后发送广播 `FE 98 00 6B`。
- `04`：设置位置模式速度，value=0..3000 RPM。
- `05`：同步触发。按顺序等待之前的缓存运动命令发出，再发送广播 `FF 66 6B`。
- `06`：应答策略，param0=1 等待驱动回包，0 不等待。
- `07`：上报掩码，value 低字节：1 基础状态、2 位置、4 速度、8 目标值。
- `08`：地址映射，value 四字节对应电机 0..3；param0 非零时设置第五地址，param0=0 保留第五地址。五个地址必须非零、互不重复；失败返回否定 ACK，映射保持不变。
- `09`：心跳。建议每 100 ms 发送一次，超过 500 ms 没有有效上位机通信会停机。

### 标准帧或扩展帧 0x201

兼容旧底盘格式，固定 8 字节：`01, motor_idx, RPM(int32 LE 四字节), reserved, reserved`。

采用加速度 50 RPM/s、立即执行，使用与 0x100 相同的地址映射、发送结果和电机索引范围。最后两个字节保留，不作为同步标志。

### 扩展帧透传

其他扩展帧保留 ID、DLC 和数据发送到 CAN2；`0x700 / 20` 保留给舵机。CAN2 回包按原 ID 和 DLC 转发回 CAN1。

仅接受有效长度的数据帧作为控制输入。远程帧、截断的底盘命令、无关标准帧不会刷新心跳。

## ACK 与状态

标准帧 0x102：`seq_hi, seq_lo, cmd, result, 0, 0, 0, 0`。

- result=0 表示本地指令处理成功或已进入发送/驱动等待队列，**不表示电机已经执行或到位**。
- result=1 表示队列拒绝、参数错误或提交失败。上位机接收队列满时也会尝试返回否定 ACK。
- 电机的真实应答单独以扩展帧转发：`功能码 02 6B` 为接收成功，`E2` 为参数/执行条件错误，`EE` 为格式错误，`9F` 为动作完成。
- 驱动回包等待超时为 50 ms，从最后一包离开硬件邮箱后开始计时；软件排队或硬件重发期间不会提前消耗回包超时。只重试读取命令，最多三次。运动命令不自动重发，避免丢失 ACK 时重复执行相对位移；超时计入统计。
- 驱动等待队列向发送队列提交时，如暂时满，会保留原请求并重试，不丢弃已接收的指令。
- 状态任务每 20 ms 运行，空闲时最多发出一次查询，按每台电机 `3A → 36 → 35` 轮询。存在待处理驱动请求时跳过查询；新运动指令会中断后台读取等待，避免缺席电机阻塞运动。
- 0x101 为状态，0x103 为统计（约每 80 ms）。速度反馈单位 0.1 RPM，X 位置反馈单位 0.1°；目标位置仍为旧接口脉冲单位。
- `3A` 的 bit7 是上电默认置位的掉电记录，不是当前故障。`83` 是正常的“上电记录 + 已到位 + 已使能”；bit3 堵转保护仍触发停机。
- 故障事件在中断写入、状态任务取出时使用原子交接，避免拷贝过程中被新事件覆盖后误清除。

## 单电机抓包示例

地址 1，持续发送心跳：CAN1 **标准帧** 0x100，DLC=8，`09 FF 00 00 00 00 00 00`，每 100 ms 一次。

正转 100 RPM：CAN1 **标准帧** 0x100，`01 00 64 00 00 00 32 00`。应在 CAN2 看到 **扩展帧** 0x100，DLC=8，`F6 00 00 32 03 E8 00 6B`。

使能命令：CAN1 **扩展帧** 0x100，DLC=5，`F3 AB 01 00 6B`。CAN2 应原样收到，驱动正常应答为扩展帧 0x100，DLC=3，`F3 02 6B`。

先设置位置速度为 100 RPM：CAN1 标准帧 0x100，`04 00 64 00 00 00 32 00`。再发送相对一圈：`02 00 80 0C 00 00 32 00`。CAN2 应看到：

| 扩展 ID | DLC | 数据 |
|---|---:|---|
| 0x100 | 8 | FB 00 03 E8 00 00 0E 10 |
| 0x101 | 4 | FB 00 00 6B |

手册 4.2.1 与 4.2.3 的续包示例写法不一致；本实现保留 4.2.3 的续包重复功能码方式，并修正有效长度。实机联调应一并核对驱动返回的 `02/EE`。

停止：CAN1 标准帧 0x100，`03 FF 00 00 00 00 00 00`。CAN2 应看到广播扩展 ID=0、DLC=4、`FE 98 00 6B`。

## 自动验证与构建

```powershell
python tools/run_host_tests.py
cmake --build build/MakeDebug --parallel 4
```

主机回归测试编译实际的 CAN、驱动、控制和中断源文件，使用模拟 HAL 验证报文字节、邮箱阻塞、失败重试、分包原子性、双向转发、地址映射、同步顺序、急停优先、发送完成计时、五电机连续指令和故障事件交接；不能替代电机实测。

固件输出在 `build/MakeDebug/STM32_Motor_Controller.hex` 和 `.bin`。

`tools/aa_packer.py` 默认生成 X 固件 F6/FB 数据，`--firmware emm` 可显式生成旧格式。AA 长度包含广播地址、功能码、长度字段和校验码；命令流最大 92 字节，与 STM32 缓冲区一致。
